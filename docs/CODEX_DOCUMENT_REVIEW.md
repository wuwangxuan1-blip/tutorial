## 结论

当前四份文档覆盖了已确认的主要产品范围：Android 原生 App、四领域、目标输入与参考教程、步骤卡片与提问、图片和短片反馈、运镜动画、咖啡配方与历史、DeepSeek 服务端调用。技术方案明确为 Kotlin + Compose / Python FastAPI。

在交给码道执行前，需要补齐下面的契约规则与执行材料。不要为修正文档删除用户已确认的功能。

## R1：条件 PATCH 的清空语义自相矛盾

位置：API_CONTRACT.md 第1003行，`PATCH /v1/sessions/{id}/conditions`。

同一段同时规定“不支持删除”“只覆盖非null字段”“null清空非关键字段”“关键字段清空回clarifying”。Android无法据此生成一致请求，服务端也无法确定校验和状态转移。

建议统一：未提供字段保持；提供非null值时替换并校验；null仅清空明确列出的可空字段；关键字段null返回422并保持现有状态；空字符串按字段校验，不兼作清空。列出可空字段，并提供请求、响应和拒绝样例。若选择允许回到clarifying，则必须同步补齐状态机、轮次数和现有计划的有效性规则。

## R2：超长参考资料的拒绝与截断规则不一致

位置：PRODUCT_REQUIREMENTS.md 第246行；API_CONTRACT.md 第757、1272行；CODING_STANDARDS.md 第199行。

产品总则规定超限拒绝；粘贴文字接口也规定413；Reference却允许按20,000字符截断；模型客户端规范要求“超限截断并标注”。相同资料通过不同入口可能得到不同内容而用户不清楚。

请选定统一规则，或明确区分上传字节限制、解析后字符限制、送模型上下文预算。建议原文超限明确拒绝；如允许用户选择部分内容，则显式确认、保留选取范围和来源，不静默改变教程。`truncated`字段应有清楚、不会与产品总则冲突的用途。

> 2026-11-04 补记：截断方案已被否决；现行规则为单条/合计 20,000 字符超限拒绝，不截断（见 API_CONTRACT 3.12/4.7/7）。

## R3：全量重新生成计划可能绕过已完成步骤锁定

位置：API_CONTRACT.md 第1018、1020–1033、610、1174行。

修订接口明确禁止修改done/skipped步骤，但plan-jobs允许已有计划重新生成，只说明检查base_plan_version，未定义已完成步骤ID、内容、证据、历史、当前步骤和计时如何保留。实现者可能覆盖正在执行的计划。

建议：未开始实践时可全量重新生成并递增版本；已有进行中/已完成/跳过步骤时，条件变化通过修订流程调整可编辑部分，或创建关联的新会话。若仍允许原会话全量生成，必须明确锁定步骤保留规则、版本提交时的二次检查及失败回滚；不允许只在Job创建时检查版本。

## R5：本地演示部署属于待确认的产品限制

位置：TECH_STACK.md 第37–38行。

文档写明手机依赖开发机FastAPI和adb reverse，并称“已接受的产品限制”。这是技术建议，用户只明确接受安卓App，尚未明确确认必须USB连接开发机的使用方式。

建议保留本地连接作为开发/比赛演示路径，删去“已接受”的表述，列为待确认的部署决策；与面向实际用户的服务端部署路径区分。无需现在部署公网或增设账号系统，也不能声称单独安装APK即可联网使用。

## 补充一致性问题

- PRODUCT_REQUIREMENTS.md 第151行称已完成步骤的修订需用户确认，第172行及API契约则完全禁止修改。统一为本期已完成/跳过步骤不可改，确认只适用于后续可编辑步骤。
- TECH_STACK.md 的模型超时默认90秒，API_CONTRACT.md 的ask说明为60秒。按端点写清请求、模型、Job和客户端各层超时，避免客户端先放弃而服务端仍创建结果。
- Timer规范使用elapsedRealtime且保存时间锚点，但需明确设备重启后单调时钟重置时的恢复策略，不能跨重启直接相减。至少检测锚点失效并让用户确认恢复，不能产生负计时。
